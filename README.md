# 松林図をあるく ― 『空白の意味』体感教材

高校2年「論理国語」で原研哉『空白の意味』（教科書 p.145〜151）を読むときに使う、ブラウザ教材です。
長谷川等伯「松林図屏風」を手がかりに、「空白は『無』ではなく、見る側がイマジネーションで満たす可能性である」という主張を、**霧の中に入る・いじる・書き込む**ことで体感します。

- `index.html` 一枚。ビルド不要。共有以外はオフラインでも動きます。
- スマホ縦（幅360px）を基準に、Chromebook の横長画面と投影にも対応。タッチ操作が基本です。
- 名前・メールアドレスなどの個人情報は集めません。

## できること（第1段階）

| 体験 | 内容 | 本文 |

| 霧の松林をあるく | スワイプ・スクロールで霧の奥へ。松が霧から現れては消え、左上の霊峰は近づかない。松風の音（既定オフ） | 149・7／149・16 |

屏風モード（六曲一双の3D表示）は第3段階で追加予定です。

### 絵について

松・霧・霊峰は、松林図をもとに**筆の打ち込みを重ねてプログラムで描いた独自の水墨風の絵**です。東京国立博物館の画像は使っていません。実物は、教科書 p.146〜147 の図版と、[東京国立博物館の名品ギャラリー](https://www.tnm.jp/modules/r_collection/index.php?controller=dtl&colid=A10471)・[ColBase](https://colbase.nich.go.jp/collection_items/tnm/A-10471) で見比べてください。

## 生徒への案内文（例）

> 今日は、原研哉『空白の意味』を「体感」します。配られたリンクをスマホか Chromebook で開いてください。
> 名前を入れる場所はありません。書いた言葉は名前なしでクラスの画面に映ります。
> 友だちが読んでいやな気持ちになる言葉や、電話番号・メールアドレスは書かないでください（書けないようになっています）。
> 最後の「振り返り」で出てくる記録をコピーして、Classroom の課題に貼り付けて提出します。

## 1時間の流れ（50分の目安）

1. 導入：うめたい度チェック（前）＋**補完ラボ 5分**
2. **描き込みスライダー 10分** ― 投票して分布を投影し、北宋画／南宋画／破墨を本文と照らす
3. **霧の松林・靄スライダー 15分** ― 霧の奥へ歩く。靄 0 と 70 を比べ、広く深く感じた濃さを記録
4. **白の向こうに書く 10分** ― 投影モードでクラスの言葉を映し、読み合う
5. **振り返り 5分** ― うめたい度（後）、ことばにする、記録をコピーして提出

授業の進め方と発問例は [docs/授業での使い方.md](docs/授業での使い方.md) にあります。

## 教員のセットアップ手順

### A. 教材を公開する（GitHub Pages）

既定のブランチに push すると、GitHub Actions（`.github/workflows/pages.yml`）が自動で公開します。最初の一回だけ、Pages が有効になっているか確かめてください。

1. このリポジトリの GitHub ページで **Settings** → **Pages** を開く。
2. **Build and deployment** の **Source** が「GitHub Actions」になっていなければ、「GitHub Actions」を選ぶ。
3. **Actions** タブで「GitHub Pages に公開」を開き、失敗していれば **Re-run jobs**（または **Run workflow**）を押す。
4. 1〜2分待つと、`https://sakadosoutan-boop.github.io/kuuhaku/` で開けるようになる。

> Actions を使わないときは、Source を「Deploy from a branch」にし、既定のブランチと `/ (root)` を選んで **Save** でも公開できます。

共有を使わない（端末内のみ）なら、ここまでで授業ができます。

### B. クラスで書き込みを共有する（Google Apps Script）

1. 学校の Google アカウントで Google ドライブを開き、**新しいスプレッドシート**を作る（名前は例「空白の意味_共有」）。
2. スプレッドシートのメニューで **拡張機能** → **Apps Script** を開く。
3. 最初からある `コード.gs`（`Code.gs`）の中身をすべて消し、このリポジトリの [`gas/Code.gs`](gas/Code.gs) の中身を貼り付けて、保存（💾）する。
4. 上の関数の選択欄で `setup` を選び、**実行** を押す。権限の確認が出たら、自分のアカウントを選んで**許可**する。シート `posts`・`votes`・`classes` ができる。
5. 左の歯車 **プロジェクトの設定** → 下の **スクリプト プロパティ** → **スクリプト プロパティを追加**。プロパティ `TEACHER_PIN`、値に教員用の PIN（例 4〜8 桁の数字）を入れて保存する。
6. 右上の **デプロイ** → **新しいデプロイ** → 種類の歯車で **ウェブアプリ** を選ぶ。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（生徒が学校の Google アカウントでログインしている Chromebook だけなら「（組織名）内の全員」でも可）
7. **デプロイ** を押し、表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピーする。
8. 教材を開き、ホームの下の **教員用** を開く。「GAS ウェブアプリの URL」に貼って **保存** → **接続を確かめる** で「つながりました」と出れば成功。
9. 同じ画面の「クラスの管理」にクラスコード（例 `2A`。英数字と `-` `_`、16字まで）と PIN を入れて **ひらく**。
10. 「生徒に配るリンク」をコピーし、Classroom などで配る（QR コードにしてもよい）。リンクを開くと、クラスコードと共有先が生徒の端末に自動で設定される。

> `index.html` の先頭近くの `CONFIG.GAS_URL` に URL を書いておけば、リンクに `gas=` を付けなくても共有先になります（クラスコードは各自入力）。

#### 授業中の操作（教員用画面）

- **受付を停止／開始**：書き込みの受付を切り替える。
- **非表示／再表示**：不適切な投稿を、投影からも生徒画面からも消す（シートには残る）。
- **投稿を全消去・投票をリセット**：そのクラスの分だけ消える。次の授業の前に使う。
- **投影モードへ**：霧の松林にクラスの言葉が大きく浮かぶ。「分布」で投票のヒストグラム、「全画面」で全画面表示。

#### 制限と負荷について

- 投稿は30字以内。NG語・電話番号・メール・URL は受け付けません。同じ端末は15秒に1回、1クラス10件まで。
- 生徒の端末は約8〜10秒ごとに更新を確かめ、画面を離れたりタブを隠したりすると止まります。GAS 側は5秒間結果を使い回すので、40人で使ってもスプレッドシートの読み取りは少なく抑えられます。
- コードを直したときは **デプロイ** → **デプロイを管理** → 鉛筆 → バージョン「新バージョン」で更新すると、URL は変わりません。

## データの保存先

| どこに | 何を |
| --- | --- |
| 生徒の端末（localStorage） | うめたい度の回答、選んだ値、書いた言葉、振り返りの文、端末ごとのランダムな識別子 |
| 教員のスプレッドシート | 投稿（クラスコード・本文・位置・端末識別子・時刻）、投票（値・時刻）、受付の状態 |

端末識別子は英数字の乱数で、名前やアカウントとは結びつきません。

## 開発・検証

外部ライブラリなし。動作確認は Playwright（Chromium）で行います。

```bash
npm run test:gas
```

```bash
npm run test:e2e
```

- `tests/gas.test.js`：`gas/Code.gs` を Node 上のモック（メモリ上のスプレッドシート・キャッシュ）で動かし、API を確かめる。
- `tests/e2e.js`：スマホ（360×740）と Chromebook（1366×768）で主な操作の煙テストとスクリーンショット（`tests/screenshots/`）。端末内モードと、GAS をモックにした共有モードの両方。
- `?q=0`（低）〜`?q=2`（高）を URL に付けるか、授業設定の「絵の描き方」で描画の品質を固定できます。ふだんは端末の性能と実測のフレーム時間で自動的に下げます。
- GitHub Actions：`ci.yml` が push ごとに両方のテストを実行し、スクリーンショットを成果物に残します。`pages.yml` が既定のブランチを公開します。
